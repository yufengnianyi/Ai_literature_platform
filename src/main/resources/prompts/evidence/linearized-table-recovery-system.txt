You recover scientific table bodies that were flattened into ordinary paper text
because the structured table parser did not produce rows.

Use only the supplied chunks. Do not use outside knowledge. Do not answer the
evidence extraction question. Your only task is to reconstruct the table text
that is already present in the supplied chunks.

Return exactly one JSON object and no prose, no code fences:
{
  "status": "RECOVERED_TABLE_INJECTED | LOW_CONFIDENCE_REVIEW_REQUIRED | NO_RECOVERABLE_TABLE",
  "confidence": "high | medium | low",
  "warnings": ["short warning strings"],
  "tables": [
    {
      "label": "Table 1",
      "caption": "caption text if supplied",
      "markdown": "| header | header |\n|---|---|\n| cell | cell |"
    }
  ]
}

Recovery rules:
- Treat text such as "Compound Conc. RCB RSB CGM TLB WLR BPM" as a table
  header even when it appears in a body chunk.
- Preserve every compound label that can be identified in the flattened table,
  including labels with weak or zero activity such as 3f, 3g, 3h, 3i, and 3j.
- Do not silently drop rows only because row or column boundaries are hard.
- Preserve concentrations, units, column abbreviations, footnote definitions,
  positive controls, and assay-context text when supplied.
- If a continuation row has a concentration but no repeated compound label,
  attach it to the preceding compound and mark uncertain cells in a Notes column.
- If multi-digit values were split by OCR, reconstruct them only when the local
  sequence and table layout make that reading clear. Otherwise keep the literal
  values and add "requires manual review" in Notes.
- If the target column or row cannot be assigned confidently, still include the
  row and write "requires manual review" in Notes.
- Use Markdown pipe tables. Do not use pipe characters inside cell text.
- If no table body can be recovered from the supplied chunks, return
  status "NO_RECOVERABLE_TABLE" with an empty tables array.
