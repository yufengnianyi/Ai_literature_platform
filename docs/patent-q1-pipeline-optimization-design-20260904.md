# 专利 Q1 流程优化设计

日期：2026-09-04。状态：待实施设计，不代表已部署或已完成性能验证。

## 1. 目标与边界

将当前“文本页筛后恢复表格”调整为“全文轻量索引、主体辅助召回、文本与版面共同找表、组装实验依据后抽取”。正确性优先，不能通过丢失实验或减少校验来换取提速。

- 不改文献 GROBID pipeline，不生成假 TEI，复用现有 artifact、ParsedTable、Q1 16 列、records API 和必填校验。
- 第一版继续只处理文档级 TEXT_LAYER_USABLE；其中局部图片页/图片表允许识别。整篇扫描件和不符合文本层要求的混合文档继续报告跳过，不能声称已覆盖。
- 主体识别是导航和排序依据，不是“只提取摘要药名”的硬过滤器。
- 区分化合物实体、组合物、受试处理组和实验结果；不能把九个处理组统计为九种新化合物。
- 本设计不启动真实提取、不安装模型、不修改生产代码。后续按指定公开号白名单验证，不自动运行全部专利。

### 2.1 性能基线的正确解读

CN106857590B 最终缓存命中轮次：入库 5.605 秒，Q1 38.862 秒，总计 44.468 秒。原 6 页保留 6 页；extractor 输入为 9 块、2,213 字符，完整增强上下文为 113 块、12,873 字符。

另一轮冷缓存表格恢复及入库为 24.249 秒，不是纯视觉耗时，也不是最终完整成功轮次。不能将两轮数据相减当作视觉服务精确耗时，不能外推批量提速比例。

共享链路已有阶段 telemetry，但历史交付报告没有拆出每次实际模型请求及前处理明细；先导出已有事件，再补缺口。对六页短专利，新增主体模型调用可能变慢。

## 3. 新流程与数据边界

```text
候选白名单与文本层检查
  -> 全文页级文本/图像对象轻量索引（缓存，保留错误）
  -> 标题/摘要/必要权利要求 -> 主体候选（只作辅助）
  -> 文本双路召回 + 独立版面候选检测
  -> 候选表统一登记、区域定位、相关性检查
  -> 可靠文本/TEI 恢复，缺失部分局部视觉识别
  -> 方法、处理组、表格、表注、结果关联
  -> 受限回查缺失引用/续表/定义
  -> 明确覆盖状态，生成实验依据包
  -> 发布兼容 artifact -> RAG 入库 -> Q1 分组抽取/审计/校验
```

全文轻量索引是可回查资料，不等于全部向量化，更不等于全部送入模型。版面检测不等于全文 OCR。页码用于定位，段落、表格和处理组才是主要抽取单位。

### 3.1 全文轻量索引

扩展 PatentPdfTextService，在同一文档处理上下文中复用 PDFBox 读取结果；每页记录：

- 物理 PDF 页码（1-based）及原印刷页码（可选，不混用）。
- 原始文本、检索用规范化文本、段落/行 ID、必要的文字位置。
- 页面尺寸、CropBox、旋转角、图像区域、文字密度和抽取状态。
- READ_OK、EMPTY、READ_ERROR 等状态；READ_ERROR 不参与“没有内容”的判断。

仅索引图像位置，不默认解码全部大图；先规则后按需渲染。原文与规范化文本分存，避免化合物名、比例和小数归一化后无法核查。原 PDF 不修改。缓存键包括 PDF SHA-256、抽取版本和坐标规范版本。

### 3.2 主体识别

新增 PatentSubjectResolver，输入标题、按标记定位的摘要、必要时的独立权利要求。记录主体类型、核心成分/通式、组合关系、文中别名、宣称病害、来源 span 和识别方法。

- 类型允许 SINGLE_COMPOUND、COMPOUND_SERIES、COMBINATION、FORMULATION、USE_OR_PROCESS、UNKNOWN，不强制只有一个主体。
- 规则识别明确的“含 A 和 B 的组合物”等模式；仅原文中明确给出的别名参与自动扩展。
- 复杂/含糊时可调用一次受字符预算限制的文本模型，输出受 schema 校验的 JSON；模型必须返回已提供的来源 ID。
- 规则与来源一致性决定是否可用于排序；模型自报高置信度不能直接授权排除正文。
- 摘要病害存 claimedTargets，不生成 assayTargets，不补病原拉丁名，不从外部实体库改名。
- UNKNOWN/模型超时不阻断全文通用召回。默认影子评估阶段不开主体模型，必要时单独做消融实验。

CN106857590B 的主体应为“噻菌灵 + 苯噻菌胺组合物”；不能在该阶段硬编码九行、5:1、表号或所在页码。

### 3.3 文本双路召回

在现有 PatentPageTriageService 内复用页索引及 PatentEvidenceSections：

1. 主体路：成分/编号/组合关系与方法、活性指标、试验描述联合检索。
2. 通用路：独立检索生测方法、Test 定义、结果段、表题、处理列和指标，不要求出现主体名称。

两路取并集。单独病害用途清单和背景功效只作上下文，不授予实测结果角色。“非活性担载体”“表面活性剂”不授予活性表角色。编号映射只在局部试验/章节范围解释，不能以全文裸数字匹配确立关联。

评分用于执行顺序，不用于抹去候选。保存召回来源、原文 span、角色、命中原因及排除依据。纯配方也可能是受试制剂的成分定义：不作为活性结果，但被实验明确引用时必须回收。

## 4. 图片表的发现与恢复

### 4.1 独立于文本页筛的候选通道

新增一个窄职责的 PatentLayoutCandidateService，输出候选区域，不做化合物数据抽取。首选评估 PaddleOCR 的 PP-DocLayout-S 独立版面检测模块，通过本地常驻服务隔离 Python 依赖；不默认运行整套 PP-Structure/OCR。后续固定依赖版本、模型文件校验和设备配置，不依赖运行时下载。

该模型的官方输出包含 table、text 等类别及坐标，适合作为候选定位器；通用版面准确率不等于本项目专利表召回率，不能引用官方耗时作为本机承诺。[官方模型页](https://huggingface.co/PaddlePaddle/PP-DocLayout-S)

分两种运行模式：

- validation_full：所有通过文本层门槛的页面都做版面候选检测，作为新能力的离线验证默认模式；只做定位，不对所有页面读表。
- balanced：优先候选实验页、图像/文本异常页及表引用目标页；拟判“无证据”前，对剩余页面补做版面检测。已有阳性但仍有页面未检查时，必须披露覆盖不足，不宣称全篇无遗漏。

几何线索只能提高优先级，不能证明无边框表不存在。检测器不可用、运行超限或低质量页面未处理时，报告 INCOMPLETE，不退回文本零命中后标记完成。检测为非表的区域也可能误判，须通过负样本抽检评估残余漏检率。

### 4.2 统一表格候选

候选来源包括 TEXT_CAPTION、TEXT_MATRIX、PDF_IMAGE、LAYOUT_TABLE、CONTINUATION；合并同页重叠区域但保留所有来源。初始字段包含 candidateId、page、bbox、captionSpanIds、sourceSignals、tableKind、state、reason。

- 表题只有“表 2”或跨行时也登记候选，不要求同一行命中活性词。
- 表题在图片内时由版面通道发现；不能依赖先得到“EC50”才能定位表。
- 没有独立图片对象时渲染页面定位；图像对象与表格不是一一对应。
- 化学结构表、制剂配方、活性表与 UNKNOWN 分别管理。UNKNOWN 在有实验关联线索时保留，不能视为无关。
- 已明确相关的候选直接完整读取，避免先做一次视觉分类又读两次的重复开销；仅含糊候选采用局部表题/表头初读，结果缓存复用。

### 4.3 区域、坐标与识别

统一坐标为“经页面旋转修正的可见 CropBox、左上角原点、归一化 bbox”；同时保存 PDF 原坐标与渲染变换。PDFBox 点坐标、模型像素坐标不可直接混用，旋转页、非零 CropBox 和超界裁剪须单测。

- 低分辨率页面定位，关键表格使用可配置高分辨率渲染；初始沿用当前成功案例的 300 DPI，而不是宣称对所有扫描图有效。
- 裁剪包括完整表头、单位、行、脚注和必要表题。边界不确定先扩大到整页确认，不能先裁掉来源内容。
- 原图分辨率过低时，提高渲染 DPI 不会恢复缺失笔画；应报告待复核。
- 可靠现有 TEI/文本优先，但行列可解析不等于内容已被独立验证；保留来源类型及校验级别。
- 关键数值表保留现有两次独立请求和逐项比对。状态宜称 READ_AGREED，而非将一致直接等同人工验证；不一致/不可辨认仍为 REVIEW_REQUIRED。
- 沿用 qwen3-vl-plus-2025-12-19、现有独立客户端、原始响应存档、60 秒超时及一次临时错误重试策略；只对读取区域变化或可修复错误重试，不做无上限重试。
- ParsedTable 保存逻辑行列；伴随审计保存每个原始行的页/片段关联。模型无法可靠返回单元格坐标时只承诺表区域和行索引，不伪造精确单元格 bbox。

跨页表依据表号、重复列名/列序和明确“续表”连接，关联不明时分开保留并待审。去掉重复表头时保留原始片段映射；长表分片读取需重叠行核对，不能把不同试验的同名列直接拼接。

## 5. 实验依据包与受限回查

新增 PatentEvidenceBundleAssembler，复用现有段落角色和表格产物，建立最小明确关系，不引入新的通用知识图谱服务。

每个 bundle 包含：bundleId、document-local assayId、受试对象/角色、方法 spans、结果 spans、tableRefs、处理行 ID、目标原文、单位/时间/重复、冲突列表、关联依据及完整性状态。

关联优先级：明确表/试验引用 > 局部编号定义及表注 > 同一实验段边界 > 邻近位置。邻近位置只生成候选，不能覆盖已有矛盾。A/B 或 Test A 在新章节重新定义时使用不同作用域；不能全篇共用一个别名映射。

支持一张 Test A-H 矩阵对应多项试验：按列组绑定测试定义，保留同一原表来源，不复制或串用试验条件。对照单剂保留 control/reference 身份；无药 CK 不能作为阳性药剂对照。

以已恢复表格反向寻找缺失对象定义、表注、单位、方法和续表；再正向检查方法引用的结果是否齐全。初始最多两轮回查，新增页面/区域受预算限制，已处理候选去重。无新增线索时终止并列出缺项。

40 页不再表示“全文只保留最高分 40 页”：保留完整轻量索引，40 页作为初始单批证据预算。多个完整 bundle 分批处理；单个超大 bundle 按表行分片，携带共同方法/表头。超出整篇资源预算则 PARTIAL，保留未处理候选清单。

## 6. Q1 接入与减少重复模型调用

- 表格恢复/关联在暂存 artifact 内完成后，再生成 document.jsonl、tables.jsonl、artifact-manifest.json，保持 PreprocessArtifactLoader 兼容且 source_tei 可为空。
- chunks 以实验段落/表格块组织，保留现有偏好的 section_path，正文前缀包含公开号、原物理页、assay/bundle/表/行标识；结构化关系存伴随文件，避免污染 Q1 16 列。
- 暂不改所有调用方的 RagChunk 公共结构；专利适配层读取伴随 bundle manifest。
- TableContextService 仅对有合法版本及原表引用的专利 bundle 接收“已确认表集合”，跳过重复模型选表。不能只是全局 table.llmSelect=false 后落入关键词路径，再漏掉弱表题的已确认表。无 bundle/旧 artifact/文献沿用原行为。
- MultiProfileEvidenceService 专利分支改为按 bundle 和行组有界批次；同一表的 EC50、CTC 等配对列不拆散，公共方法/表注随批次带入。
- verifier 使用对应 bundle 的完整依据及冲突，而不是无差别扩回所有背景；仍保留原始完整资料供审计与回查。
- 预期处理组从恢复表行动态建立，不硬编码 CN106857590B 的九行。去重键须区分 assay、对象、配比、条件和指标，技术重复与独立试验不混淆。
- 先本地校验行数、比例、数值和引用，只有可修复的输出不一致才调用限次修正。缺少原文拉丁名等不可补齐信息不反复请求模型猜测。
- 保留 verifier、INVALID 候选及实体改名关闭设置；不以关闭质量检查作为性能优化。

## 7. 状态、缓存、接口与发布

### 7.1 状态分开表达

不把任务执行、发现覆盖、证据质量混在一个 COMPLETED 中：

- workflowStatus：原有入库/任务执行状态兼容保留。
- discoveryStatus：COMPLETE、PARTIAL、REVIEW_REQUIRED、FAILED、NOT_APPLICABLE。
- extractionStatus：沿用实际 Q1 任务状态；行级 VALID/INVALID 按现有规则。
- discoveryOutcome：EVIDENCE_FOUND、NO_EVIDENCE_FOUND、UNRESOLVED。

COMPLETE 指按记录策略完成检查，不是数学意义证明没有遗漏。未恢复的疑似实验表、读页错误、检测器故障或预算截断均不能得到完整负例结论。没有摘要主体可正常完成通用发现；缺病原拉丁名可以形成完整来源证据，但记录 INVALID。

本阶段默认严格发布：相关关键表未读清或关联不明时保留暂存产物，旧可用索引不变，暂不提交该文档到正式 Q1。明确标记部分结果的发布模式后续另行实现，不混进首轮性能对比。

### 7.2 可重现与缓存失效

各阶段缓存键必须包含 PDF 哈希、对应阶段策略/模型/提示版本及相关配置。视觉键额外包含页、坐标、旋转、渲染参数和实际提供的上下文；关联缓存包含表格内容哈希。错误响应和空表不是成功命中。

force=true 表示新建 run 产物并重建本篇下游结果，不等于强制付费重读已验证相同图片；冷缓存实验显式使用独立 cache namespace，不删除旧结果。

修正当前仅凭 canonical document 存在且有向量即可复用的条件：必须同时匹配 PDF 哈希和 artifact/pipeline/config 版本。不匹配时生成新产物后重建，不能复用旧页筛结果。

继续复用原 documentId 并保留旧产物。发布前完成静态校验；同一文档重建期间加互斥并阻止并发提取读取混合版本。向量与 BM25 不是自动原子事务，重建失败应明确 FAILED/恢复流程；不宣称只换 storageRoot 就实现无损原子切换。零停机版本索引不在本轮范围。

### 7.3 最小接口与产物变更

现有 POST 可增可选 strategyVersion（初期默认 legacy；v3 显式启用）、discoveryMode 和 subjectMode；其余预算优先置于服务配置并写入现有 config_json。旧请求与 publicationNumbers 过滤保持兼容。

GET run/documents 增加可选 discoveryStatus、discoveryOutcome、candidateTableCount、unresolvedCount、bundleCount、timingSummary、artifactVersion；保留原计数语义，不把表数/处理组数叫作化合物数。

新增伴随文件：

- patent-page-index.jsonl：原文与页级状态/位置索引。
- patent-subject.json：主体、来源、规则/模型版本。
- patent-table-candidates.jsonl：所有候选及最终处理/排除原因。
- patent-evidence-bundles.jsonl：实验关联、原表行引用、缺项与冲突。
- patent-discovery-audit.json：覆盖页、未处理项、预算及回查记录。
- patent-stage-metrics.jsonl：跨入库和 Q1 的计时关联。

保留现有 patent-demo-pages.jsonl、patent-table-manifest.json、图像、原始视觉响应和 Q1 审计。供 SQL 筛选的发现状态以新迁移增加必要列；详细区域/模型响应留在文件，不建设新的一整套数据库表。

## 8. 计时和预算

复用 EvidenceAgentTelemetryService 及现有 Q1 scopeId，用 demoRunId、extractionRunId、documentId、bundleId 和 tableId 关联两阶段。已有事件先导出，新增只补未覆盖阶段和真实调用次数。

阶段包括 PDF_OPEN、TEXT_SCAN、SUBJECT、TEXT_RECALL、LAYOUT_DETECT、TABLE_CLASSIFY、TABLE_RENDER、VISION_READ、BUNDLE_LINK、BACKTRACK、ARTIFACT_WRITE、INDEX_REBUILD、TABLE_SELECT、EXTRACTOR、VERIFIER、PERSIST。

每次记录开始/结束、elapsedMs、状态、cacheHit、输入/输出规模、模型、真实请求数、重试和排队/等待。provider 返回 token usage 时才记录 token；不可用写 null，不用字符数冒充 token。共享 telemetry 的预设 llmCalls 不应代替真实请求计数。

父阶段 inclusive 时间与子阶段分开；并行请求壁钟时间不等于子请求耗时之和。报告冷缓存/热缓存、服务启动/模型预热、成功/失败轮次；实际性能承诺必须来自本机结果。

## 9. 实施顺序与验收

### 阶段 A：基线及防漏门控

先导出/补齐计时、页级错误和覆盖状态；保留新旧两路影子结果。将无证据门控从表格恢复前移走；新候选状态可进恢复但不直接授予“已验证 Q1”。旧六页金标准及三篇负例离线回归。

### 阶段 B：统一表候选及版面通道

保留 CN106857590B 的成功路径，补无文本表题、无独立图像对象、旋转、表注及跨页表。模型服务先做离线可用性/坐标/性能验证，未通过不默认上线。只对明确白名单做真实识图。

### 阶段 C：主体辅助与实验关联

先规则主体，再按需模型；建立 bundle、局部编号作用域及最多两轮回查。按表组/试验组输入 Q1，复用确定选表结果，核验 verifier 未重新引入背景宣称。

### 阶段 D：兼容发布及对照评估

验证新旧 artifact、API、迁移、强制重跑、缓存失效和重建失败路径。v3 初期 opt-in，通过召回/忠实性门槛再考虑切换默认；服务异常不能静默标为成功。

### 9.1 固定正确性用例

- CN106857590B：定位方法/表 1 的实际第 3–4 页；九处理组、九 EC50、七 CTC 全部匹配来源。0.881、0.198、5:1 的 0.378/147.97；保留 2 d / 72 h 冲突、原文病害、空拉丁名和 INVALID。六个制剂配方不是六次已验证药效试验。
- 原三篇负例：权利要求/用途清单/背景功效不新增已验证 Q1；本轮不自动重新付费抽取。
- 构造/人工标注页：表题与表体均为图片、只有表号、跨行表题、矢量表、同页多个表、跨页表、旋转/CropBox、低清图像、星号剂量标记和空单元格。
- 引用负例：远距离方法、同名 Test 重定义、A/B 重定义、不同试验重复配比、对照药不在摘要、配方被明确引用。
- 故障用例：读取异常、模型超时、坐标越界、预算上限、旧空缓存、版本不一致、服务不可用；均不得伪造完整负例或覆盖旧可用结果。
- 共享兼容：文献 TEI、无 TEI artifact、线性化表格、Q1 16 列、记录计数和来源锚点回归。

### 9.2 性能实验设计

建议下一轮明确授权后使用 10 篇固定白名单分层样本，包含短组合物、长化合物系列、图片表/无文本表题、跨页表和无实验证据负例。每篇在 baseline 与 v3 使用同 PDF、同模型和同输出要求，分别测冷/热缓存。首次 10 篇只是诊断 pilot，不足以宣称大规模准确率或稳定 P95。

进行消融：baseline、仅补表候选/关联、再加规则主体、再加按需模型主体。额外模型调用增加耗时却无召回或正确性收益时，不开启该功能。

报告实验页/表/处理组召回、数值与归属准确率、宣称误入率、未决比例、送入模型字符/实际 token、真实调用/重试数、成功与失败壁钟时间。金标准来自独立原文标注，不能用同一流水线输出作为召回率分母；训练/规则调优样本与后续盲测分开。

验收优先级：固定金标准不退步，新增图片表用例不漏；然后看耗时和成本。不能承诺每篇提速；若完整覆盖检查更慢，明确报告质量收益和时间代价。
