- 入库的 4 份原文共 51 页，保留 19 页，页数减少 62.7%。该比例不代表证据召回率。
- 产生 6 行候选，其中 2 行自动标记 VALID、4 行 INVALID。33.3% 是自动校验通过率，不是人工准确率。
- 原页复核发现，2 行 VALID 仍遗漏核心数值，并存在混配结果归属问题。当前结果不能直接验收为完整 Q1 数据。
- 统计来自此前运行记录；本轮核对了源码、已有 artifacts，并沿用前一轮原 PDF 相关页的人工复核结果，未重新查询已停止的数据库服务。

## 2. 表格方案：优先复用现有 Q1 能力

### 2.1 当前 Q1 的真实处理链路

已从源码确认：

```text
EvidenceChunk.sourceTei
  -> TableContextService.augment
  -> TableJsonlStore.load
  -> TableJsonlMaterializationService.loadOrMaterialize
  -> 读取 TEI 同目录的 tables.jsonl，或从 TEI 生成该文件
  -> TeiTableParser 解析 figure[type=table] / table / row / cell
  -> 选择相关表格
  -> TableLegendResolver 补充表注、编号解释及支持引句
  -> 注入 table_body chunks，继续 Q1 抽取和校验
```

结构化表格缺失或不适用时，`LinearizedTableRecoveryService` 会检查提供的文本 chunks，尝试重建被线性化的表格，输出 `table_body_recovered`。这条路径依赖文字里确实存在可恢复的行、编号和数值，不是对图片进行 OCR。

`TeiTableParser` 对没有 `<row>` 的图片表或仅表题节点，明确输出 `structured=false` 和空数据行。因此应区分三种情况：

| 输入情况 | 处理方案 | 能力边界 |
|---|---|---|
| TEI 已有行列及数值 | 复用现有解析、表注解析、表体注入 | 优先路径，无需重新识图 |
| 数值在正文中，但表格被压平 | 复用文本表格恢复，补充中文专利表头、行号和单位规则 | 只能重排原文中已有数据 |
| 数值只存在于图片中 | 先记录缺失并定位原 PDF 区域；下一版用局部 OCR 或视觉读取后转成统一表格产物 | TEI 表题或图片引用本身不能提供缺失数值 |

### 2.2 专利 demo 尚未接通的部分

当前专利 artifact 不生成 TEI，chunk 的 `source_tei` 是空字符串，`tables.jsonl` 是空文件，抽取 overrides 又设置了 `table.enabled=false`。

只把 `table.enabled` 改为 true 不够：`TableContextService` 找不到 `sourceTei` 就直接返回，连文本表格恢复也不会执行。另外，当前 `loadOrMaterialize` 会直接接受已存在的空 `tables.jsonl`，不会仅因内容为空就重新解析 TEI；内存缓存也需要版本或失效管理。

建议按以下顺序接入，保留 Q1 已有的表格分析及证据校验能力：

1. 有真实 TEI 的专利，优先读取并检查其表格内容；不要生成假路径满足接口条件。
2. 无 TEI 的当前 demo，推荐增加专利表格 artifact 读取入口，让 TEI 解析、PDF 文本表格恢复及后续图像补读统一提供表格对象。页码、区域和来源方式可放在伴随元数据中，避免为缺失字段伪造 `rawTeiXml`。
3. 再复用 Q1 的表格选择、编号解析、表注补充、证据 chunk 注入与校验。调整入口前须按项目规则对实际修改符号运行 impact，并验证原文献路径不回归。
4. 若希望完全沿用 TEI 入口，可试验“筛选后的页段生成 TEI”，但这改变了首版完全绕过 GROBID 的边界。必须保留精简 PDF 页码到原始 PDF 页码的映射，单独测量成本和表格召回，不能假定能够恢复图片表。
5. 为“尚未解析”“解析完成但无表格”“发现表格但表体缺失”建立不同状态；表格更新后刷新磁盘产物和内存缓存。

首版不做 OCR 的约束下，纯图片表可以被准确标记为待补读，但不能把“缺失数据”解释成原专利未报告，也不能验收为完整抽取。

## 3. 例子一：实际试验与用途宣称为什么必须分离

### CN118339136A：适用病原不等于实际试验病原

该专利中段列举了多种作物病害及其病原，包括疫霉、腐霉等。当前页筛保留了这些用途清单，模型随后生成了“式(I)化合物对多个卵菌有效”的候选行。

但第 17 页的实际试验例 1、2、3，测试对象分别是玉米黑穗菌 `Ustilago maydis`、宫部旋孢腔菌 `Cochliobolus miyabeanus` 和禾谷镰刀菌 `Fusarium graminearum`，均非卵菌。该页有具体培养、浓度和测量条件，却没有被选入。

错误发生在把两种陈述拼接起来：

```text
用途段落：本发明化合物可用于包含疫霉等病原的病害防除。
实际试验：化合物 1、2 在其他病原试验中出现生长抑制。
错误推导：化合物 1、2 已经针对用途清单中的疫霉完成上述试验。
```

正确处理：保留用途清单作为背景信息，实际试验按明确测试对象登记；本篇在已核对证据范围内不产出 Q1 卵菌实证记录。它可以包含其他抗真菌证据，但那属于另一个提取范围。

### CN111418597A：背景介绍不能补出实验对象

第 3 页背景称吡唑醚菌酯可以控制包括卵菌纲在内的多类病害。第 12–13 页实际表格列出根腐病、青枯病、纹枯病、基腐病等防效，但未明确对应卵菌病原。不能仅凭背景中的“卵菌纲”，把这些防效标成某个卵菌的实验结果。

### 建议的证据准入

先定位试验，再确认同一试验的“测试实体、病原或病害、方法、结果”之间的联系。浓度、时间、对照和指标定义应一并关联；必要内容可以跨页，不要求出现在同一句或同一页。

背景和宣称仍可保留，但应记录来源角色。建议区分 `TESTED`、`CLAIMED_USE`、`BACKGROUND`、`INSUFFICIENT_EVIDENCE`。病害名称缺少明确病原时保留原文，物种规范化或推断需要独立来源标记，不能冒充原文给出的拉丁名。

缺少剂量不应一律删行：如果确有试验、结果和对象关联，仍按现有 Q1 标准保留指标并标注缺失条件；只有用途宣称而没有试验依据，则不能依靠“缺少剂量”占位语将其变成实证。

## 4. 例子二：页筛与表格判定为什么会出错

### 4.1 把“非活性担载体”当成活性表

CN118339136A 第 2 页是权利要求，其中有“化合物”和“非活性担载体”。当前 `ACTIVITY_TABLE_HEADER` 的中文分支允许“化合物”后 180 个字符以内出现“活性”等词，因此会命中“非活性”的子串，且不要求存在真实表头、数值行或列对齐。

结果：第 2 页被标记为 `ACTIVITY_TABLE`，生成 `patent/result/activity-table` chunk，并连带保留邻页。第 5、7、14 页也被记录为活性表，实际主要是化合物、载体或制剂说明。角色标签进一步让后续模型把这些段落当作结果证据。

解决方向：

- “化合物 + 活性”只作为弱候选信号，不能直接授予活性表角色。
- 对“非活性担载体”“表面活性剂”等短语作局部语义排除，不能因为一页出现这些词就丢弃整页。
- 表格确认结合表题、表头、重复行列、数值或等级、单位及版面结构；图片表体不可读时进入待补读，而不是判为无表。
- 权利要求可保留为实体或用途上下文，但不会因这类弱命中被提升为实验结果。

### 4.2 真正的试验页反而被漏掉

同一专利第 17 页包含完整“试验例1–3”，但当前测试定义规则偏向 `Test A–H` 和“卵菌词靠近试验词”。因为该页测试的是其他病原，未被选中，系统失去了核对用途清单的实际试验上下文。

解决方向：先轻量识别完整试验章节，再判断其中是否存在 Q1 相关试验。对于已因用途词命中的专利，至少检查实际试验对象；确认无 Q1 依据后，可仅保存筛选判定和来源定位，不必把所有非 Q1 试验送入昂贵抽取。

### 4.3 选中页面也不等于选中数据

CN106857590B 第 4 页已入库，但图片“表1”的表体未进入文本。该表有 2 个单剂和 7 个混配比例的 EC50 数据，现有两行结果只概括了增效关系。

解决方向：增加“原页存在表格但 artifact 缺表体”的完整性检查。验收同时检查页面召回、表体召回和数值归属，不能仅统计保留页数。

## 5. 专利问题清单

P0：直接导致错证据或核心数据丢失；P1：影响完整性和可追溯性；P2：规模化前完善。部分能力也适用于文献，此处强调其在专利数据中的具体表现。

| 编号 | 优先级 | 问题与现象 | 解决方案 | 验收标准 |
|---|---|---|---|---|
| PAT-01 | P0 | 用途病原清单被当成实际测试对象 | 按试验组装实体、病原、方法、结果；记录背景与宣称角色 | CN118339136A 不再产生缺乏卵菌试验支持的 Q1 实证行 |
| PAT-02 | P0 | 权利要求中的“非活性担载体”等触发活性表标签 | 关键词降为弱信号，结合行列、表头、单位和版面确认 | 第 2、5、7、14 页不再因这些语句标成活性结果表 |
| PAT-03 | P0 | 专利 artifact 未接通 Q1 表格增强 | 增加真实表格来源适配，复用现有表格选择、表注与编号解析；区分空缓存状态 | 专利表体能够进入 Q1，原文献表格回归测试通过 |
| PAT-04 | P0 | 文本 PDF 中图片表数值缺失 | TEI 表格优先，已有文本恢复其次；纯图片表定位并标待补读，后续局部识别 | CN106857590B 表1的 9 个 EC50 与 7 个混配 CTC 被正确恢复；未补读时不得报告完整 |
| PAT-05 | P0 | 单剂、混剂与制剂被混为同一测试实体 | 保存单剂实体及混配组成、比例；活性和 CTC 绑定实际处理组 | 单剂 EC50 不被混剂结论替代；7 个混配比例数据均有对应处理组 |
| PAT-06 | P1 | 中文“试验例”“生物测定”等章节漏筛 | 先分章节再判实验对象；覆盖中文和数字试验编号 | 能定位 CN118339136A 第17页并作出非 Q1 的判定 |
| PAT-07 | P1 | 固定邻页与 40 页截断破坏证据联系 | 根据试验、表号、脚注及化合物引用补齐上下文；超预算拆分证据组 | 不留下无定义的 Test 列；必要上下文超限时标记不完整或分批处理 |
| PAT-08 | P1 | 化合物号、合成例、制剂例、通式相互混淆 | 建立专利内局部映射；通式、具体结构及测试实体分开；只展开被实际测试的实体 | 通式(I)不冒充单一具体化合物；实施例编号正确关联测试配方或化合物 |
| PAT-09 | P1 | 星号、等级、剂量及配方百分比含义混淆 | 从表注解析星号和等级，不预设其含义；区分母液、最终测试浓度、制剂含量与施用量 | 无表注的星号标记未解析；浓度不从配方百分比直接推算 |
| PAT-10 | P1 | 原专利条件冲突被自动合并 | 各字段保存原文位置；对时间、单位和比例作一致性检查 | CN106857590B 正文2 d与表头72 h同时保留，并标记冲突 |
| PAT-11 | P1 | 背景机制、抗性宣称被当成实验验证 | 记录字段的证据角色与验证方法；支持原文报告不等于支持已实验验证 | “可延缓抗性”不会被写成已完成抗性试验；没有验证方法时不补造 |
| PAT-12 | P1 | 页码前缀有溯源，但精确证据锚点缺失 | 文本保存原句及段落号；表格保存原页、区域、行列和识别来源 | 每条接收记录可回到原始文本或表格位置；重建表标记为派生产物 |
| PAT-13 | P1 | 文档级文本阈值掩盖局部图片或混合页 | 抽样判定后检查候选页质量；区分无文本、短文本、乱码和表体缺字 | 关键表格图片页可被独立发现；短篇不因统一字符阈值直接认定扫描件 |
| PAT-14 | P2 | 不同国家、公开与授权版本重复计数 | 保存公开号、申请号、优先权及家族关系；按实际证据去重并保留版本差异 | 同一试验跨版本不被算成独立重复验证，新增数据仍可保留 |

## 7. 建议实施与回归顺序

1. 建立四篇专利的人工标注基线：区分用途段、实际试验段、表格区域、测试实体和关键数值。它们是开发回归集，不用于宣称总体准确率。
2. 修复 PAT-01、PAT-02、PAT-06，阻止错误证据进入抽取，并保留必要的实验对象检查。
3. 接通 PAT-03 的 Q1 表格复用，检查表格产物是否包含数据，不以生成了文件作为成功条件。
4. 处理 PAT-04、PAT-05：纯图片表补读属于下一版新增能力；完成后核验单剂与每个混配比例的对应关系。数据点数量不等于最终 Q1 行数，可按既有行粒度合并，但须可逐点追溯。
5. 补足条件、编号映射、来源和冲突标记；对没有明确卵菌实验依据的三篇，不要求产出实证行。
6. 扩展独立样本，覆盖英文长专利、Test A-H、跨页表、纯图片表、混合页、无相关试验的负例和专利家族。分别评估页面召回、表体召回、实体映射准确性、数值准确性及证据准入准确性。
