## 实际调试问题

1. 两次识图曾共同把 CTC 表头识别为 CC。加入原页对缩写的明确定义辅助辨读后恢复表头，没有引入外部数据。
2. 450 DPI 渲染和低分辨率原生位图曾把一格 120.57 读成 120.37。差异触发 REVIEW_REQUIRED，阻止入库；没有选择一方数字强行通过。
3. 最终使用同一可读 300 DPI 区域发起两次独立请求，并另存原生位图。两次独立请求不等于两个独立模型，仍可能共同误读，因此还执行逐格目视基准核对。
4. 仅添加提示词时，模型仍复制背景机制并漏标时间冲突。改为实际过滤非实验段落、动态生成来源时间冲突提示，并加入逐项审计后解决。
5. 模型曾只在增效栏写裸 CTC 数值。明确要求 `CTC=原表值` 后通过，未改写数值。
6. 配比校验原先可能把相邻单元格数字粘连；已改为逐单元格读取。实测 CTC 与定义增效的阈值也分别处理。
7. records API 原有 SQL 将参数与 ORDER BY 连在一起，返回 500。补充分隔后已实际验证返回九条记录。

总共进行 7 轮同一专利的调试/复验，其中两轮在读表阶段被拦截，另有 Q1 审计失败轮次。一轮虽然得到九条数值记录，但仍有背景机制和时间标注问题，未算最终验收成功。失败审计、旧 Q1 输出和历史产物均保留；不能把中间轮次的 COMPLETED 当作本报告的验收结论。
