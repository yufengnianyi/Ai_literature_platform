# 结构化证据存储设计

## 数据粒度

系统以一条可独立审核、引用和版本化的证据事实作为核心存储单位。文献是来源维度，问题是分类和聚合维度，`文献 × 问题` 是提取任务与状态统计单位。

| 层级 | 表 | 职责 |
| --- | --- | --- |
| 文献 | `rag_document` | 文献身份、题录和原始内容来源 |
| 分类任务 | `evidence_document_question_match` | 文献对问题的支持状态、置信度和提取状态 |
| 提取运行 | `evidence_question_extraction_run` | 模型、配置、版本、耗时和运行结果 |
| 证据事实 | `generic_evidence_record` | 单条问题相关事实及审核状态 |
| 原文锚点 | `generic_evidence_anchor` | chunk、章节、位置及原文引句 |
| 翻译版本 | `evidence_record_translation` | 与源证据分离的多语言派生结果 |

## 证据载荷

`cells_json` 在兼容期继续保存位置数组。新写入同时生成 `payload_json`，字段名来自对应 `profile_version` 和 `question_id` 的字段定义：

```json
{
  "gene_protein_name": "PsCRN63",
  "pathogen_species": "Phytophthora sojae",
  "functional_perturbation": "过表达",
  "common.evidence_level": "直接验证"
}
```

读取历史记录时，如果 `payload_json` 为空，应用层根据原有 `cells_json` 和版本化字段定义生成同等的键值载荷。完成历史数据重新提取后，可以再移除位置数组兼容逻辑。

## 版本与翻译

- `profile_version` 决定问题编号、字段键和字段语义。
- `row_fingerprint` 在一次提取范围内去重。
- `supersedes_record_id` 连接相同指纹的前后版本。
- `is_current` 标记当前可用版本，历史记录继续保留以供审计。
- 翻译以 `(record_id, language_code, prompt_hash)` 唯一，重新翻译不会覆盖源证据。
- 原文证据保存在 `generic_evidence_anchor.exact_quote`，翻译载荷不能替代原文锚点。

## 查询策略

- 文献详情：按 `document_id` 聚合问题匹配和当前证据。
- 问题视图：按 `profile_version + question_id` 聚合跨文献证据。
- 字段检索：使用 `payload_json` 的 GIN 索引。
- 审核队列：使用现有 `review_status + is_current` 索引路径。
- 无证据结果：保存在文献问题任务的 `NO_EVIDENCE` 状态，不创建空证据行。

数据库变更由 `V40__add_keyed_evidence_payload_and_translations.sql` 提供。
