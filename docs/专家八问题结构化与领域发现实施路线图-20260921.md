# 专家八问题结构化与领域发现实施路线图

日期：2026-09-21。

目标：以专家提供的八个问题为首批框架，从文献正文、表格和补充材料中积累可追溯的结构化数据，再进行分型、条件分层比较和证据综合，形成可由专家核验的领域发现候选。

本轮完成需求梳理、源码核对、专家字段快照和实施安排。应用当前仍运行旧 Q1–Q10；本文中的新数据结构、八题路由和分析流程均为待实施方案，不代表已迁移、已跑模型或已得到科学发现。

## 1. 本次需求基线

- 新 Q1–Q8 替代旧十题作为后续开发主线。保留逐篇分类、按题抽取、表格输出、原文追溯和人工复核的需求模式。
- 化合物仍须提取正文与表格数据，迁移到新 Q5 后保留表头、脚注、编号解析、数值、单位、对照和补充材料的对应关系。
- 八题是专家先验，不是模型自动发现的八类。后续在各题内部归纳子类型、条件差异和结果关系，并保留框架外候选。
- “分型”暂按研究对象、机制、表型、实验场景和证据强度的分层编码与分析理解；不预先限定为遗传分型或纯无监督聚类。
- 首个产品验收对象是可分析的证据数据集及其分析结果。Wiki 页面、问答和报告消费这些数据。

来源为用户提供的 `8个问题.docx`。已按 OOXML 表格读取全部内容：8 张问题字段表、1 张 Common Evidence 表及1张问题总览表；无批注、修订或内嵌图片。文档中的示例只用于解释字段，不能写入事实库当作真实抽取结果。

[专家字段快照](专家八问题字段快照-20260921.json) 原样保留中文名、英文键、是否必填、类型、示例、抽取说明与表外原则，同时记录原文件 SHA-256。快照含 161 个分题字段和 17 个 Common Evidence 字段；这不是每条记录都需填满的 178 项。

分类采用多标签。同一篇论文可进入多个问题，同一实验可贡献不同科学主张。新 Q1 不再照搬旧 Q6 的“排除效应子”规则：是否进入 Q1/Q2 应分别检查功能扰动和宿主互作证据，而不是强制二选一。

## 3. 架构定位与现有基础

本项目适合采用“LLM 辅助构建的领域证据数据库 + 证据驱动的 Wiki + 原文 RAG”。Wiki 指可更新、可追溯的实体和专题知识视图，是本项目采用的设计方式，不把这个名称当作已有完整功能的证明。

```text
论文及补充材料
  -> 解析正文和表格 -> 文献筛选 -> 八题多标签分类
  -> 按题抽取原文值及锚点 -> 数值与实体标准化 -> 质量检查和复核
  -> 领域实体库 + 八题记录 + 实验观测 + Common Evidence
  -> 可比性分层 -> 类型编码及跨文献分析 -> 发现候选与证据地图
  -> 实体/专题 Wiki、问答和报告

原文 RAG 为抽取、核验、补缺和问答提供材料；新增事实须重新经过抽取与审核。
```

| 现有能力与源码 | 可复用部分 | 本次需要补齐的部分 |
| --- | --- | --- |
| `EvidenceProfileRegistry` | 按题字段、行粒度和指导规则 | 八题定义、稳定字段键、实体角色和题集版本 |
| `generic_evidence_record`、`generic_evidence_anchor` | 通用记录、审核、原文锚点 | 命名字段、字段级证据、实验条件和观测结构 |
| `entity_library`、`entity_review_candidate` | 实体、别名、来源与候选审核 | 生物学身份范围、外部编号、实体关系和记录实体链接 |
| `EvidenceReconcilerAgent` | 抽取后实体匹配入口 | 不覆盖原文名；按类型和物种消歧；持久化稳定实体 ID |
| `TableContextService` 等 | TEI 表格加载、表格选择、编号说明和线性化恢复 | 保留化合物能力并解除旧 Q1 编号绑定 |
| `DeepReportPipelineService` | 证据矩阵、补检索、全文分析、引用校验 | 从化合物为主扩展为按题的数据分析与发现档案 |
| `problem_discovery` | 来源、缓存、运行产物和专家审阅组织 | 归纳输入由摘要问题转向已抽取的科学记录；尚未实现该转换 |

核对范围为仓库源码与迁移脚本，未查询运行数据库，所以不以建表脚本推断当前实体数量或数据质量。

## 4. 基础底表如何设计

### 4.1 扩展已有实体库

现有 V28 已定义实体库，不新增平行的“名词总表”。在现有主表上增加必要字段或附属表，按以下职责组织：

| 结构 | 关键内容 | 用途 |
| --- | --- | --- |
| 实体主表，扩展 `entity_library` | 稳定 ID、实体类型、标准显示名、物种/身份范围、状态 | 回答研究对象是谁 |
| 别名与外部编号 | 原名、别名、数据库命名空间和 accession、适用物种/菌株/文献范围、来源 | 合并同物异名并避免同名异物 |
| 实体关系 | 主体、关系、客体、证据、审核状态 | 表达编码产物、同源、变体等关系 |
| 记录实体链接 | 记录 ID、字段键、角色、实体 ID、原文提及、匹配依据与状态 | 让八题数据能跨论文关联 |

首批类型覆盖基因、蛋白、基因位点、变异、化合物、病原物种、宿主物种、菌株/材料、通路/生物学过程；干预对象、检测方法和模型按 Q7/Q8 接入。只纳入实际语料用到的对象，不先建设大而全的术语库。

身份规则：

1. 基因与蛋白分别建实体，存在明确依据时用 `encodes` 关联；原文无法区分时保留待消歧提及，不强行二选一。
2. 基因名相同而物种不同，不自动合并。优先使用可靠的数据库命名空间、编号、物种及版本；名称归一只是候选匹配依据。
3. 别名、同源物、等位变体不是同一种关系。专家表的 `alias_homolog` 可保留展示，但内部拆开表达。
4. 论文内的 Compound 1、蛋白简称和菌株编号保留适用范围，不能仅凭名称跨论文合并。
5. 效应子、宿主靶标和抗性相关因子通常作为角色或功能标签，不因为同一对象在不同题里承担不同角色就重复建实体。
6. 保留 `raw_mention` 和标准实体链接，不能把原文名直接替换成标准名后丢失来源。未知对象允许先以候选实体或未解析链接入库。
7. 自动匹配不把模型常识当作论文证据。外部数据库补充信息另记来源与获取版本，不回填为“论文已报告”。

目前 `EvidenceReconcilerAgent` 按主字段索引推断类型、匹配 `entity_type + normalized_key` 并可能替换单元格；部分旧题共用 `OOMYCETE_ENTITY`。新实体连接需替换这一粗粒度映射，并检查停用实体、歧义别名与跨物种同名情况。

### 4.2 实体身份与实验事实分开

“某蛋白是谁”属于实体；“该蛋白敲除后，在某菌株及条件下毒力下降”属于证据记录。不要把某次实验结果直接固化成实体全局属性。

建议复用现有记录和锚点，在分析需要的位置增补以下结构，物理表名在实现时确定：

| 结构 | 最小字段 |
| --- | --- |
| 科学记录 | `record_id`、`paper_id`、题集版本、稳定 profile key、专家原字段值、抽取/审核状态 |
| 实验背景 | 实验 ID、物种/菌株、宿主/材料、生活史阶段、处理和对照、剂量、时间、温度、场景 |
| 观测 | 记录/实验 ID、终点、原始值、比较符、数值/范围、单位、误差/重复数、对照、显著性 |
| 字段级证据 | 记录/字段/观测 ID、Chunk、图表号/行列/脚注、原文短句、证据类型和等级 |
| 跨记录链接 | 记录间共享实验、同一原始研究、转述引用或支持关系，附来源 |

八题主表保持专家所需的浏览和导出形式。多值字段在主表可用分号展示，内部采用数组或关联记录，保持数值、处理条件和证据一一对应，不把不同实验拼成不可计算的长字符串。

Common Evidence 是所有题的共享证据规范。`paper_id` 对应现有文献标识，`record_id` 对应独立科学记录；DOI 等优先引用文献主表。物种、菌株和实验背景与主表字段出现重复时采用同一内部来源生成，避免两份独立可编辑值不一致。

### 4.3 缺失、证据等级与计算值

专家原文同时要求“部分字段必填”和“未报告则留空”。字段快照忠实保留两者；以下为实施建议，不冒充专家已经确认的规则：

- 区分系统必需项与科研信息完整性。记录 ID、文献、题集版本等由系统保证；科研字段缺失时不补造事实。
- 表格仍显示空白，内部至少区分 `NOT_REPORTED`、`NOT_APPLICABLE`、`NOT_EXTRACTED`、`PARSE_FAILED`、`AMBIGUOUS`。
- 无机制但有明确活性数据的新 Q5 记录保留并标记不完整；未找到证据不等于作者未报告。关键字段缺失进入复核与分母统计，不静默丢弃。
- “无显著差异”、明确负结果和“缺失”分开。保留作者推测，与直接实验验证分开。
- 模型置信度、引用锚点有效性、科学证据等级、人工审核状态分别记录，不相互替代。
- 保留原始数值与单位。只能在换算条件充分时生成标准值，并记录转换规则；分子量未知时不把质量浓度转换为摩尔浓度。
- 专家 Q6 要求 RF 按论文报告记录。系统额外计算的 RF 存为派生观测并标注公式与输入，不冒充原文 RF。

## 5. 化合物表格能力的保留与迁移

化合物由旧 Q1 移到新 Q5，但 16 列旧模型与 19 列新专家表并非同一个 schema。第一条样板链路必须验证：

1. 仍能读取正文表格、脚注及已取得的补充表；未取得或解析失败的材料必须有状态。
2. 化合物编号与结构/名称的对应有依据；同一编号在不同论文内隔离。
3. 剂量、时间、物种/菌株、测定方法、终点、数值与单位共同构成观测，不交叉错配。
4. 阳性对照及其结果单独关联；EC50、MIC、抑制率和田间防效不能混排成统一强弱榜。
5. 多时间点、多剂量和多终点在内部拆成多观测，导出时按专家主表组织。
6. 靶标为候选还是已验证，依据论文方法和结果判断；保留直接或间接证据的差异。
7. 不把“只抽前三个代表化合物”等旧截断规则默认为新数据集的完整抽取方式。样板全量抽取表内符合范围的记录；如因预算截断，显式记录范围与未完成项，不用于总体覆盖结论。

下列位置已核实依赖旧 Q1，必须在切换前一起处理：

| 位置 | 改动要求 |
| --- | --- |
| `PromptCatalog`、`EvidenceProfileRegistry` | 按题集版本和稳定语义标识解析模板及字段，不能只改展示题号 |
| `EvidenceExtractionAgent`、`EvidenceMarkdownTableParser` | 新 Q5 的 19 列契约与旧化合物 16 列分离，按字段键映射 |
| `EvidenceProperties`、`LinearizedTableRecoveryService`、`PatentQ1EvidenceSupport` | 表格增强及专利兼容按化合物能力选择，不让新 Q1 基因误入化合物逻辑 |
| `MultiProfileEvidencePersistenceService`、`CompoundEvidenceRow.fromCells` | 避免新 Q1 错写化合物表；新 Q5 不直接按 16 个索引解析 |
| `EvidenceReconcilerAgent` | 字段实体类型从新 profile 元数据获取，保持原名与实体 ID |
| 聊天、报告、导出、批处理脚本与前端题目选择 | 使用同一题集定义；历史结果显示历史题名，兼容既有化合物消费链路 |

## 6. 版本与历史数据

当前 `MultiProfileEvidenceModels.PROFILE_VERSION` 已是 `oomycete_questions_v2`，但其内容仍为旧十题。新专家题集建议使用独立标识 `expert_q8_20260921_v1`，不能把“v2”误当成已切到八题。

稳定业务标识建议为 `gene_function`、`host_interaction`、`host_resistance`、`genome_evolution`、`compound_activity`、`fungicide_resistance`、`intervention`、`diagnosis_surveillance`。Q1–Q8 是该题集下的展示编号。

- 分类批次、抽取运行、记录、缓存键、导出与数据集快照都携带题集/schema 版本。
- 历史十题只读保留。旧 Q1 不改写成新 Q1，旧字段不足的行不伪装成新表完整记录。
- 历史结果先做候选迁移映射，保存 `derived_from_record_id`；合并题和新增字段优先从原文重新分类、抽取。
- 去重、`is_current` 更新范围及查询条件需要包含适当的题集/语义标识，避免新运行使旧题结果被错误失效。
- 先完成版本契约与兼容测试，再切换新运行默认题集；历史读取继续走旧 schema。
- 导出同时包含原始记录、规范化观测、实体链接、证据与运行清单。缓存不能跨题集误复用。

## 7. 如何从结构化数据得到发现

### 7.1 三步推进

先按专家字段做确定性的多维分型，再让模型提出子类型，最后形成有依据的比较结论。八题之间不做一次全量文本聚类来代替科学比较。

| 题目 | 首批分型或比较维度 | 首批分析产物 |
| --- | --- | --- |
| Q1 | 生物学过程、扰动方式、表型方向、物种与阶段、互补验证 | 功能–表型证据矩阵，区分直接验证与表达相关 |
| Q2 | 因子家族、宿主靶标、互作直接性、作用位点、验证方法 | 互作机制类型及支持/反对证据 |
| Q3 | 基因或位点类型、免疫层级、宿主材料、抗性谱、逃逸 | 抗性机制与适用病原背景地图 |
| Q4 | 研究设计、样本群体、变异类型、参考版本、关联表型 | 群体与基因型–表型关联证据分布 |
| Q5 | 化学类别、病原、终点、实验条件、靶标证据、应用阶段 | 可比活性组、机制证据层级与体外到活体的验证覆盖 |
| Q6 | 药剂、抗性机制、突变、RF、遗传背景、代价、田间发生 | 抗性机制分型与交互抗性证据表 |
| Q7 | 干预类别、作用对象、递送方式、剂量、应用场景 | 干预效果与应用条件分布 |
| Q8 | 记录类型、样本、技术、地区/年份、验证设计、预测时距 | 检测方法比较、监测分布、模型外部验证覆盖 |

“跨题连接”先产出可核验路径，例如 Q1 的功能扰动、Q5 的靶标证据、Q6 的抗性变化和 Q7 的干预结果是否涉及同一实体。路径存在只说明材料可关联，不自动证明新机制或因果关系。

### 7.2 可比性是分析前置条件

- 数值比较固定终点、单位、病原/菌株、测定方法、时间和场景；允许合并或需要分层的维度由分析协议显式定义。
- 同一论文、同一实验或同一原始数据集的多行不能当作多个独立研究。分别统计记录数、实验数、独立研究数和文献数。
- 综述转述与原始研究关联去重；作者推测、专利用途宣称和实际实验分别标记。
- 先描述性汇总和证据地图，再判断是否满足定量合并条件；缺少方差、对照或条件时不强行做总体效应。
- Q8 的 AUC、RMSE、LOD 等对应不同任务与验证设计，不能按数值大小组成统一模型或方法排行榜。
- 没有抽到某字段只产生“待核验缺口”。在当前语料未找到证据，不等于整个领域从未研究。

### 7.3 发现候选档案

每项发现候选保存：明确主张、适用范围、分析规则及版本、支持与反对记录、独立研究数、可比性限制、检索语料范围、专家判断和下一步验证方式。

分清三个层次：已发表结果的整理、跨文献形成的综合观察、需要进一步查新/实验验证的新假设。只有完成相应验证，才能提高结论等级。

模型可以建议类型名称、整理机制描述和撰写解释；计数、筛选、单位转换和统计由可复现代码完成。初版分型允许多标签、未归类和待定，专家修订保留版本与归属理由。

## 8. Wiki 在项目中的具体作用

实体页聚合标准名、别名、所属物种、关联论文、不同条件下的结果、争议和待补证据；专题页汇总某题及其子类型的证据分布。页面从结构化数据和审核结果生成，不单独维护一份无来源的“权威答案”。

页面至少记录实体/专题 ID、生成时间、数据集快照、依赖记录 ID 和审核状态；记录被修订、撤回或实体被合并后，将相关页面标为过期并重建。正文结论关联具体证据，不把多个矛盾结论压成一句无条件描述。

建议页面内容顺序为对象身份、已报告结果、条件差异、证据强度、冲突、待核验问题及原文链接。RAG 用于回查与补缺，Wiki 不是后续抽取的唯一事实源，以免生成内容循环放大。

先实现可审阅的数据详情与分型视图，再扩展完整 Wiki 页面和通用聊天。PostgreSQL 可以承载首版实体与关系，Neo4j 保持可选，不作为首轮交付的前置条件。

首批开发集建议每题选择 5–10 篇有全文的代表文献，可重叠；专门加入跨题论文、负结果、复杂表格、缺字段与不支持该题的对照材料。样板集用于找错，不据此声称总体准确率。独立测试集按论文及重复研究分组隔离，数量由试点评估所需精度确定，不能把同篇不同表格分到开发和测试两侧。

### 9.2 测试与科学质量验收

| 范围 | 必查事项 |
| --- | --- |
| 版本迁移 | 旧 Q1 仍是化合物；新 Q1 是基因；新 Q5 是化合物；缓存及当前状态不串版本 |
| 表格抽取 | 合并表头、脚注、多个剂量/终点、对照、单位、不等号、原文编号及补充表关联 |
| 实体链接 | 同名不同物种不合并；别名与同源分开；基因/蛋白及变体不混同；未解析允许保留 |
| Common Evidence | 每条记录可定位原文；每个关键数值能定位到对应实验与表格单元；引用存在且语义支持 |
| Q8 条件字段 | 六种记录类型合法；同篇多记录；不适用字段不作为抽取遗漏；不派生新题号 |
| 分型与统计 | 多标签去重、独立研究计数、可比性过滤、空组/缺失、重复运行稳定性与人工修订保留 |

科学评价分别报告文献分类 precision/recall、科学记录抽取 precision/recall/F1、关键字段及数值单位准确率、证据支持率、实体链接 precision/recall、分型审核一致性和人工修订时间。按题目、原文/表格来源、记录类型和证据等级分层，并报告样本量、分母、待审量和不确定性。

建议在盲测前与专家冻结试点目标，例如关键字段准确率 >=90%、数值单位准确率 >=95%、记录召回率 >=80%、自动合并实体准确率 >=98%。这些是候选验收目标，不是当前成绩或行业标准；高风险错误单独列出，不能只用一个平均分掩盖。小样本只用作诊断，不能可靠证明 98% 等高比例目标。

RAG 指标继续保留，但不作为本轮唯一验收依据。分别测“给定正确全文时的抽取质量”和“从筛选、分类到抽取的端到端记录召回”，失败文献留在端到端分母；否则上游遗漏会被掩盖。
